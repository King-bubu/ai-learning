# 我的 AI 学习记录仓库

2026-10-15 起，到 2027-01-30，做出一个「别人打开链接就能用」的 AI 应用。

从零开始学大模型应用开发，每天一个可运行的产出。技术栈全部本地化：Ollama 跑模型，Python 写逻辑，FastAPI 对外提供服务，不依赖任何付费 API。

---

## 现在能做什么

一个跑在本机的知识库问答服务：

- 读 `docs/` 目录下的 `.txt` 文件，按空行切段（当前 12 段）
- 用「两字组合」做字面匹配，检索出最相关的一段
- 把这段资料拼进 prompt，再交给本地模型回答
- 通过 HTTP 接口对外服务，**多用户会话隔离**（`session_id` 区分不同人的对话账本）

### 接口

| 方法 | 路径 | 作用 | 请求体 |
|---|---|---|---|
| GET | `/health` | 健康检查 | — |
| POST | `/ask` | **纯聊天**，不查资料，靠模型自己的知识 | `{"question": "...", "session_id": "..."}` |
| POST | `/askf` | **带知识库检索**（ask with files） | `{"question": "...", "session_id": "..."}` |

> `session_id` 就是「账本封面上的名字」。同一个 `session_id` 共用一个对话历史，不同 `session_id` 互相看不到对方说过的话。

**问知识库里的事，用 `/askf`；只是闲聊，用 `/ask`。**

用错接口不会报错，只会得到一段听起来很专业、实际上没有依据的回答 —— 这正是本仓库要反复对抗的那类问题。

## 怎么跑起来

**前置条件**

- Windows + Anaconda（Python 3.12）
- [Ollama](https://ollama.com/) 已安装，并且拉过模型：`ollama pull qwen2.5:3b`

**三步启动**

```powershell
# 第 0 步：确认 Ollama 活着（没反应就双击桌面上的 Ollama 程序）
ollama list

# 终端 A：起服务，起完不要关
uvicorn day07_api:app --reload

# 终端 B：调它
python day07_test.py
```

终端 A 看到这两行才算起来了：

```
INFO:     Uvicorn running on http://127.0.0.1:8000
INFO:     Application startup complete.
```

浏览器打开 <http://localhost:8000/health>，看到 `{"status":"ok"}` 就成了。

**注意**：服务和测试必须各占一个终端。`uvicorn` 不会退出，会一直占着终端。

## 已知限制

诚实地写在这里，因为它们都是下一步要解决的：

- **检索是字面匹配**：靠「两字组合」重合度打分，换个说法就可能选错段。向量检索在计划的 12 月。
- **会话存在内存里**：服务一重启，所有人的对话历史全丢。
- **只在自己电脑上**：还没有部署，别人访问不到。
- **每次问答会把整段历史发给模型**：对话变长之后会越来越慢。
- **没有测试集**：现在只能靠手问几句，无法衡量「改了检索之后是变好还是变坏」。
